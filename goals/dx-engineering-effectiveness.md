### DOCTRINE — repository-independent, carried untagged

- **A check yields zero assurance in three separate ways**, kept separate because the remedies
  differ and the signatures are opposite: wrong **set** (a confident wrong answer) · failure
  encoded as a **value** (a confident empty answer) · **never produced a verdict** (silence).
  The first two presuppose execution; the third does not, which is why neither can see it.
- ⚠ **Any instrument built for one of those inherits the other two.** Before publishing a
  measurement, ask what its own population, encoding, and verdict-producing capability are.
- **A loud break outranks a red.** An instrument that dies gets fixed within the hour; one that
  silently finds nothing becomes a guard reporting OK forever.
- **Search with a known-positive control, and pair it with a known-negative from real data.** The
  positive proves the control *can* fire; only the negative shows it does not fire *wrongly*, and
  a false positive reads as health. A fixture contains only the failure you already imagined.
- ⛔ **A control is itself a population.** If the control does not fire, the run is **VOID, not
  negative**. The regress terminates on something known **by construction** — an entity you just
  created, or one observed in the very listing being tested.
- ⛔ **A limit you have only described is a defect you have not looked at.** The tell is never
  having run the input. `NOT-YET-MEASURED` exists for this; a described limit is that state filed
  as though it were measured.
- **A content matcher cannot tell doing X from talking about X.** Match on something a mention
  cannot produce: a nonce, a position, a structural form, an effect.
- **When a fix lands in one of N sites, the finding is not the fix — it is the N.**
- **Substantive reasoning goes in the durable artifact, never only in a message.**
